================================================================
 TIMER_LAB —— STM32F429 定时器综合实验
================================================================
开发板：正点原子阿波罗 V2 STM32F429（STM32F429IGTx, LQFP176）
配套：  DNF429-EB 嵌入式学习实验箱
时钟：  HSE 25MHz（PH0/PH1）-> PLLM=25 / PLLN=360 / PLLP=2 -> SYSCLK 180MHz
        HCLK 180MHz / APB1 45MHz / APB2 90MHz
        Over-Drive 模式 + 稳压器 Scale1 + Flash 5 等待周期
调试：  SWD（PA13/PA14），用实验箱自带的 DAP 仿真器

参考：《STM32F429 阿波罗开发指南》第 19/20/21/23 章
      《阿波罗V2 硬件参考手册》引脚分配表

----------------------------------------------------------------
 一、按键操作
----------------------------------------------------------------
    UP  (PA0)  = 切换 / 翻页 / 换模式
    K0  (PH3)  = 确认 / 启动 / 反应按键
    K1  (PH2)  = 返回主菜单
    K2  (PC13) = 实验五「刹车确认恢复」
    板载蜂鸣器：每次按键「滴」一声；实验二抢跑、实验五刹车有专门提示音

----------------------------------------------------------------
 二、五个实验
----------------------------------------------------------------
1) OLED 显示
   - 实现 OLED 初始化 / 清屏 / 字符 / 字符串 / 十进制整数显示
   - 屏幕显示实验名 + 姓名 + 学号 + 每秒递增的计数值
   - 统一显示接口（需求要求的三个）：
         Disp_Clear()                  清屏
         Disp_String(x, y, "文字")      指定像素位置显示字符串（自动识别中英）
         Disp_Int(x, y, 12345)         指定位置显示十进制整数
   - 底层（写命令/写数据）在 oled.c，上层文本在 display.c，完全分离

2) 随机反应速度测试器        【基本定时器 TIM6】
   - TIM6 1ms 更新中断建立时间基准（中断里只计数 + 置标志）
   - K0 开始 -> 随机等待 2~5s -> 点亮提示 LED(PE10) 并开始计时
   - 按 K0 后显示本次反应时间（ms），并记录最好成绩
   - 提示灯未亮就按键 = 抢跑，专门提示
   - 每按一次只算一次（边沿事件，长按不重复触发）

3) 三色流水呼吸灯            【通用定时器 TIM3，三路 PWM】
   - TIM3 CH2/CH3/CH4 = PB5(蓝) / PB0(绿) / PB1(红)，PWM 1kHz
   - 三种模式，UP 切换：
         [同步呼吸] 三路同相位平滑呼吸
         [三色流水] 三路相差 120 度，亮度依次起伏
         [警灯闪烁] 红蓝交替快闪
   - K0 暂停 / 继续

4) 频率与占空比自测仪        【通用定时器 TIM4 输出 + TIM3 输入捕获】
   - TIM4_CH3(PD14) 输出 PWM，用杜邦线接到 TIM3_CH2(PB5)
   - UP 切换三个测试点：100Hz/25%、1kHz/50%、10kHz/75%
   - 屏幕同时显示：设定值、测量值、相对误差
   - 拔掉跳线后 150ms 内显示「无信号」，不再显示旧数据

 5) N 次闪光与硬件急停        【高级定时器 TIM1】
    - UP 选 N（1~9），K0 启动，TIM1_CH1(PE9) 精确闪 N 次后自动停止
    - 闪光频率 5Hz，每次亮、灭各约 100ms；默认 N=3 的总时长约 0.6s
   - 边沿对齐下溢出周期 = PWM 周期，所以要 N 个脉冲就写 RCR = N-1
   - OPM 单脉冲模式：更新事件时硬件自动清 CEN
   - PB12 接 BKIN：按键按下 -> 硬件异步清 MOE -> 输出立刻进入安全状态
     并且 AOE=0，刹车撤除后不会自动恢复，必须按 K2 确认

 三、定时器时钟与参数计算（实验要求的知识点）
----------------------------------------------------------------
1. 定时器内核时钟怎么来的
     SYSCLK = 180MHz
     AHB    = SYSCLK / 1   = 180MHz
     APB1   = AHB / 4      = 45MHz   -> APB1 定时器 = 45 x 2 = 90MHz
     APB2   = AHB / 1      = 90MHz   -> APB2 定时器 = 90 x 2 = 180MHz
   * APB 预分频不为 1 时，定时器时钟是 PCLKx 的 2 倍，所以不能拿 CPU 主频当输入
   * 90MHz：TIM2~7、TIM12~14      180MHz：TIM1、TIM8~11

2. 更新频率     f_update = f_TIM / ((PSC+1) * (ARR+1))
   本工程实际取值：
     TIM6 (90MHz)  1ms 基准 : PSC=89  -> 1MHz，ARR=999  -> 1kHz
                              分辨率 1us，最大定时 65.536ms（16 位）
     TIM3 (90MHz)  1kHz PWM : PSC=89  -> 1MHz，ARR=999
      TIM1 (180MHz) 5Hz 闪光 : PSC=35999 -> 5kHz，ARR=999
     TIM4 (90MHz)  自测仪输出：为了占空比分辨率取 ARR+1 接近 10000
          100Hz  : PSC=89 -> 1MHz， ARR=9999   占空比步进 0.01%
          1kHz   : PSC=8  -> 10MHz，ARR=9999
          10kHz  : PSC=0  -> 90MHz，ARR=8999

3. PWM 占空比   D = CCR / (ARR+1) x 100%
   同一定时器的多个通道共用 PSC 和 ARR，只各自设 CCR
   本工程 LED 统一低电平点亮，所以「亮度 = 1 - 占空比」，
   代码里写的是 CCR = FULL - 亮度

4. 输入捕获量程与误差
     TIM3 捕获计数频率 = 90MHz / (89+1) = 1MHz（1us 分辨率）
     16 位计数器 -> 单次可测最大周期 65535us -> 最低频率 15.3Hz
     周期计数值 N  -> 频率 = 1MHz / N
     误差主要来自 1us 量化：
        100Hz (10000 计数)  : 量化误差约 0.01%
        1kHz  (1000 计数)   : 约 0.1%
        10kHz (100 计数)    : 约 1%    <- 量程上端误差明显变大
     占空比由「高电平计数值 / 周期计数值」得到，同样受 1us 量化限制
     若测量更高频率，应把 PSC 调小（提高计数频率）；测更低频率，
     要么调大 PSC，要么用溢出计数扩展量程

5. 高级定时器三个关键位
     RCR : 重复计数器（带影子寄存器）。写 RCR = N-1，第 N 次溢出才产生更新事件
           -> 边沿对齐下正好输出 N 个 PWM 周期
     OPM : 单脉冲模式。更新事件时硬件自动清 CEN，所以发完 N 个自己就停
     MOE : 主输出使能。高级定时器不置 1 就完全没有输出
     BKIN: 刹车输入。触发后硬件异步清 MOE，OCx 进入 OIS 设定的空闲态；
           AOE=0 -> 不自动恢复；BIF 置位 -> 软件可查知并需要人工确认

 四、接线表
----------------------------------------------------------------
【详细版请看 WIRING.txt】—— 里面除了接线清单，还有 6 张示意图，
并且用一整节讲"引脚是怎么推导出来的"（需求→外设→定时器→通道→候选引脚→
排除冲突→排针），学会了自己就能给别的实验排引脚。
示意图在 tools/wiring/ 目录：
    01_led_basic.png       外接 LED 的统一接法（低电平点亮）
    02_header_p5.png       P5 排针引脚分布（标出本工程用到的脚）
    03_exp3_rgb.png        实验三 三色 LED 接线
    04_exp4_jumper.png     实验四 跳线
    05_exp5_flash_bkin.png 实验五 闪光 LED + 急停按键
    06_overview.png        五个实验接线总览

【统一规则】所有外接 LED 都是【低电平点亮】：
            正极（长脚）经 1K 限流电阻接 3.3V，负极（短脚）接引脚

【依据】硬件手册 LED 原理图（已从 PDF 抠图核实）：
        VCC3.3 --[R62 510R]-- DS0(红) -- PB1(LED0)
        VCC3.3 --[R65 510R]-- DS1(绿) -- PB0(LED1)
        LED 由 VCC 经限流电阻、再经 LED 到 MCU 引脚，即 MCU 灌电流，
        所以【输出低电平点亮】，且没有三极管，引脚可直接做 PWM 调光。
        （所以本工程 PWM 写的是 CCR = 满量程 - 亮度）

【无需接线】
    4 个板载按键、板载蜂鸣器（PCF8574 的 P0）
    OLED 模块 —— 直接插到板上 P6（OLED/CAMERA 接口），靠左插，右边两个孔位空着

【需要接线】
    实验二  提示 LED        PE10
    实验三  蓝色 LED        PB5
            绿色 LED        PB0   （板载 DS1 也接在这里，会一起呼吸，正常）
            红色 LED        PB1   （板载 DS0 也接在这里）
    实验四  跳线            PD14 <==杜邦线==> PB5
                           （PB5 此时是 TIM3_CH2 复用输入，不是推挽输出，
                             可以安全直连，不会两个输出对拉）
    实验五  闪光 LED        PE9
            急停按键        直插按键一端接 PB12，另一端接 GND
                           （PB12 内部上拉，不按为高 = 刹车无效）

    实验三和实验四都用 PB5，但它们是互斥的菜单模式，不会同时工作。

【引脚在哪个排针上找】
    P5 排针（1x16，按顺序引出 FMC_D0~D15）：
        1脚=D0=PD14   7脚=D6=PE9    8脚=D7=PE10   13脚=D12=PE15
    P2 / P3 排针（各 2x22，共 86 个 IO）：PB0 / PB1 / PB5 / PB12 在这些排针上，
        按板上丝印找对应引脚名即可。

【跳线帽注意】
    P11（PA9/PA10 - CH340 串口）与实验无关；
    BOOT0 排针保持默认 0，用 DAP 的 SWD 下载。

 六、编译与下载
----------------------------------------------------------------
【方式1：命令行】
    在本目录执行 make all，产物在 build\：
        TIMER_LAB.elf / .hex / .bin
    然后双击 flash.bat 烧录（自动挑最新的 elf，并先清掉占用 DAP 的 openocd）

【方式2：CubeIDE】
    File -> Import -> General -> Existing Projects into Workspace
    目录选 D:\STM32Projects\TIMER_LAB
    注意：调试探头要选 OpenOCD + CMSIS-DAP（本机用的是正点原子 DAP，
          不是 ST-LINK），OpenOCD 脚本用工程里的 openocd_cmsis_dap.cfg。

 七、已知事项 / 待确认
----------------------------------------------------------------
1. OLED 接口模式（由模块背面的 BS0/BS1/BS2 决定）
   本工程默认按正点原子官方【8080 并口】驱动。引脚映射出自开发指南 23.2 节，
   并且已用板上 P6（OLED/摄像头接口）排针旁的丝印逐脚核对过，确认无误：
       PB7=CS  PB4=RS  PH8=WR  PB3=RD  PA15=RST
       D0~D7 = PC6 PC7 PC8 PC9 PC11 PD3 PB8 PB9
   若屏幕全黑，说明模块不是 8080 模式，换模式重编即可（不用改源码）：
       make clean all IFMODE=SPI      # 4 线 SPI
       make clean all IFMODE=IIC      # IIC
   然后双击 flash.bat 烧录。
   （等价做法：直接改 Inc/pinmap.h 里的 OLED_IF_MODE 宏）
   三种模式均已确认能 0 error 编译通过。

2. 姓名 / 学号怎么改（不用手工跑脚本）
   改 Inc/config.h：
        #define STUDENT_NAME    "你的姓名"
        #define STUDENT_ID      "你的学号"
   然后直接重新编译即可。Makefile 里挂了依赖：
   只要 Inc/config.h 或 Src/app.c 里的中文字符串有变化，构建时会自动
   调用 tools/gen_font.py 重新生成 Inc/oledfont.h。
   生成器只扫描【字符串字面量】里的汉字（不扫注释），所以不会把注释
   里的字也塞进字库。
   若某台机器没装 Python/Pillow，那一步会被忽略并沿用已有字库（不会
   中断构建），此时新加的字会显示成 "?"，需要手工执行：
        py tools\gen_font.py Inc\oledfont.h tools\ui_strings.txt .
   细节见 tools/README_FONT.txt。

3. 引脚复用提醒
   PB0/PB1 接板载 DS0/DS1；PE9/PE10/PD14 是 FMC 数据线，
   本工程不使用 FMC/SDRAM/LCD，所以可以安全当普通 IO / 复用功能使用。
   将来若要做 LCD 或 SDRAM 实验，这些脚会冲突，需要重新规划。

4. 修订记录（本轮自检发现并修复的问题）
   a) BSP_Rgb_Init 的 PSC 公式写错，会得到 1Hz 而不是 1kHz
      （90MHz/(1000x1) 而非 90MHz/(1000x1000)）—— 已修
   b) exp5_task 忘了清 s_need_draw，会导致整屏刷新在主循环里每圈都跑 —— 已修
   c) Disp_Fixed1 对 -0.1~-0.9 会把负号丢掉（C 除法向零截断）—— 已修
   d) oled.c 的 IIC 分支里把 GPIOC 写成了不存在的 GPIO_C —— 已修
   e) 实验四的显示布局会超出 128 像素被截断 —— 改为按实际数字宽度动态排布
   另：BKIN 引脚用 GPIO_MODE_AF_PP + GPIO_PULLUP + AF1 的写法，
       与开发指南 21.4 节官方代码一致，不会把引脚拉死。
