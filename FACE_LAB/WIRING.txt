================================================================
 FACE_LAB 接线指南 与 引脚解析（实验四 人脸录入与识别）
================================================================
板卡：正点原子阿波罗 V2 STM32F429（STM32F429IGTx, LQFP176）
配套：DNF429-EB 嵌入式学习实验箱
外接：7 寸 800x480 RGB 屏（RGBLCD 接口）+ ATK-OV5640 摄像头（P6）
板载：W9825G6KH SDRAM（32MB，帧缓冲/图库/特征/模型）、
      W25Q256 SPI NOR Flash（32MB，人脸库持久化）、双色 LED、4 个按键

本工程与实验三（SMART_HOME）的硬件差别只有一处：
    多了【板载 W25Q256 SPI NOR Flash】这一路（SPI5：PF6~PF9），
    其余（FMC + LTDC + DCMI 三套总线）与实验三【逐脚完全相同】。
也就是说：三套总线同时开，PE/PD/PF/PG/PH/PI 几乎被占满，
外接部分只有两处"对插"：7 寸屏 + 摄像头。

★ 本工程最大的硬件特点是"几乎不用接线"，所以本文档的重点是：
    1) 每个模块【插到哪里、怎么插、方向怎么对】；
    2) 上电、跳线帽、仿真器这些【真机操作】；
    3) 引脚为什么只能是这些（方法），以及坑在哪。

----------------------------------------------------------------
 0. 先看总览：哪些要接线、哪些对插就行
----------------------------------------------------------------
    ┌──────────────┬────────────────────┬──────────────────────┬────────────────────┐
    │ 模块         │ 接到哪里           │ 怎么接               │ 备注               │
    ├──────────────┼────────────────────┼──────────────────────┼────────────────────┤
    │ 7 寸 RGB 屏  │ 板上 RGBLCD 接口   │ 对插（按丝印对齐）   │ 20 根 LTDC + 背光  │
    │ ATK-OV5640   │ 板上 P6（OLED/CAM）│ 对插（2x8 插 2x9）   │ 与 OLED 互斥       │
    │ W25Q256      │ 板载（SPI5）       │ 不用接               │ PF6~PF9 板上已连   │
    │ SDRAM        │ 板载（FMC）        │ 不用接               │ 帧缓冲 750KiB      │
    │ 双色 LED     │ 板载 DS0 / DS1     │ 不用接               │ 绿灯=通过/红灯=不通过│
    │ 4 个按键     │ 板载               │ 不用接               │ K0 拍照 / K2 换模式│
    │ 仿真器       │ 板上 20 针 JTAG/SWD│ 对插实验箱的 DAP     │ CMSIS-DAP，选 SWD  │
    └──────────────┴────────────────────┴──────────────────────┴────────────────────┘

    结论：本工程【一根杜邦线都不需要】就能跑起来。

    ★ 两个前提必须同时成立，否则上面的结论不适用：
      1) 7 寸屏是"座子对插"版本（本实验箱标配）。若你的屏是杜邦线引出，
         就要按第 2 节的信号表把 20 根 LTDC + 背光逐根接上；
      2) 摄像头走板载 P6 座子。若用排线转接，按第 3 节的引脚表接。

----------------------------------------------------------------
 1. ★ 上电与调试接线（真机操作第一步）
----------------------------------------------------------------
  1.1 供电
      板上总开关：K1（板上丝印 POWER）——控制整板供电
      外部电源输入：DC_IN（标准直流电源插座），范围 DC 6~15V
          常用做法：12V/1A 适配器，或实验箱板载的 DP100 数控电源
                    （用 DP100 时注意先设好电压，不要超过 DC 口标注范围）
      上电判断：看板上电源指示灯（PWR LED）——亮 = 上电正常；
                不亮请先确认 K1 是否按下（官方 FAQ 第 1 条就是这个）
      ★ 不要用仿真器给开发板供电：手册 2.12 明确写"不能，也不建议"
        （开发板功耗较大；DAP 若设了 5V 输出更要小心）

  1.2 启动跳线帽（BOOT0 / BOOT1）
      板上有 BOOT0/BOOT1 两颗跳线帽，用来选择启动模式（手册 2.1.8 节）。
      正常运行（从内部 Flash 启动，本工程一律如此）：
          BOOT0 = 0（接 GND）
          BOOT1 = 0（接 GND）
      只有用串口 ISP 下载时才把 BOOT0 拨到 1，下载完必须拨回 0，
      否则程序不会从 Flash 运行（表现为"下载成功但没反应"）。

  1.3 仿真器（下载与调试）
      板上是【20 针标准 JTAG/SWD 座】，直接对插实验箱标配的 DAP 排线。
      调试器务必选【SWD 模式】，不要用 JTAG，原因是：
          摄像头占用了 PB3 / PB4 / PA15，而它们同时是 JTAG 的
          JTDO / NJTRST / JTDI —— 挂 JTAG 会和 SOP 的 SCCB/复位抢脚。
          只用 SWD 的话，占的是 PA13(SWDIO) / PA14(SWDCLK)，这两个脚
          在 IO 分配表里写明"没接任何外设"，正好空出来。
      （板上另有 P1：5P 的 SWD 排针，默认没焊接，需要自己焊。）

  1.4 上电顺序（按这个顺序做，出问题最容易定位）
      1) 断电状态：把 7 寸屏插到 RGBLCD 接口（按丝印对齐、缺口方向对好）；
         把 ATK-OV5640 插到 P6（靠 3V3/GND 那端起插）；
         把 DAP 排线插到 20 针 JTAG/SWD 座。
      2) 确认 BOOT0 = BOOT1 = 0。
      3) 合上总开关 K1，看 PWR LED 是否亮。
      4) 程序启动后的现象（屏幕从上到下）：
             标题（实验四 人脸录入与识别）
             → SDRAM 自检结果
             → NOR Flash 状态（JEDEC ID / 是否载入图库）
             → 进入【录入模式】实时预览，右下侧栏提示
                "K0拍照录入 K2换模式"
         若 SDRAM 自检失败或 LCD 初始化失败，程序会停在提示画面上
         （见第 9 节的故障排查）。
      5) 下载新固件：命令行在本目录 make all 后双击 flash.bat；
         或用 STM32CubeIDE 导入本目录后 Download。
      6) ★ 插拔摄像头/屏之前一定先断电（K1 断开）。
         带电插拔 P6 有可能把 DCMI 的输入脚打坏。

 2. 7 寸 800x480 RGB 屏 —— 接板上 RGBLCD 接口
----------------------------------------------------------------
    接口：板上丝印 RGBLCD 的座子（与 TFTLCD 共用一组 LTDC 信号线）
    接法：按板上丝印对齐插入，注意座子的缺口方向，插反了会没显示
    信号：20 根 LTDC 信号（数据 16 根 + CLK/DE/VSYNC/HSYNC 4 根）
          + 1 根背光控制 PB5
    极性：行/场同步低有效、DE 高有效、像素时钟上升沿采样
          （这四位写在 bsp_lcd.c 的 LTDC_Init 里，换屏第一件事就是核对这里）

    LTDC 信号与引脚（全部 AF14）：
    ┌──────────┬────────────────────┬──────────────────────────────┐
    │ 信号     │ 引脚               │ 说明                         │
    ├──────────┼────────────────────┼──────────────────────────────┤
    │ R3~R6    │ PH9 PH10 PH11 PH12 │ 红色高 4 位                  │
    │ R7       │ PG6                │ 红色最高位                   │
    │ G2~G4    │ PH13 PH14 PH15     │ 绿色低 3 位                  │
    │ G5~G7    │ PI0 PI1 PI2        │ 绿色高 3 位                  │
    │ B3       │ PG11               │ 蓝色低 3 位的最高一位        │
    │ B4~B7    │ PI4 PI5 PI6 PI7    │ 蓝色高 4 位                  │
    │ CLK      │ PG7                │ 像素时钟（PLLSAI 出 30MHz）  │
    │ DE       │ PF10               │ 数据使能                     │
    │ VSYNC    │ PI9                │ 场同步                       │
    │ HSYNC    │ PI10               │ 行同步                       │
    │ 背光 BL  │ PB5                │ 普通 GPIO，高电平点亮        │
    └──────────┴────────────────────┴──────────────────────────────┘

    ★ 为什么只有 R3~R7 / G2~G7 / B3~B7，没有 R0~R2 / G0~G1 / B0~B2？
      板上的 RGBLCD 接口只引出了高 5/6/5 位，低 3 位没接。这正好就是
      LTDC 的 RGB565 像素格式（R[7:3] G[7:2] B[7:3]），所以本工程用
      RGB565 最自然，也比 RGB888 省一半 SDRAM 带宽（750KiB/帧 而非 1.5MiB）。

    ★ 为什么说"屏只能对插、不能飞线"？
      IO 分配表在这些脚上明确标注"该 IO 连接 RGBLCD 的 CLK/VSYNC 信号，
      【未引出】，不能做普通 IO 用"——也就是说这些信号在板上是硬走线，
      根本没有引到排针上，所以不存在"用杜邦线接屏"的做法（除非屏本身
      就是杜邦线引出、而板座上也留了对应排针——那属于改装，本文不覆盖）。

----------------------------------------------------------------
 3. ATK-OV5640 —— 插板上 P6（丝印 OLED/CAMERA）
----------------------------------------------------------------
    接法：直接插 2x9 的 P6 排针，靠 3V3/GND 那一端开始插，
          2x8 的模块插 2x9 的排针，另一端空 2 个孔是正常的
    SCCB：SCL = PB4，SDA = PB3，【软件模拟】（板上已有 4.7K 外部上拉）
          阿波罗板没有给摄像头留硬件 IIC，只能软件模拟，约 200kHz
          （SCL 边沿间延时 2us；SCCB 上限 400kHz）
    复位：RST = PA15，低电平有效；板上该脚有 10K 上拉
          驱动里拉低 10ms（手册要求 >=5ms）→ 拉高 → 等 30ms（>=20ms）
    时钟：模块【自带 24MHz 有源晶振】→ 所以主控【不驱动 PA8(DCMI_XCLK)】，
          本驱动完全不配置任何时钟输出
    数据：DCMI 8 位并行 + PCLK/HREF/VSYNC，全部 AF13
    PWDN：P6 座子上根本没有引 PWDN 脚，所以不需要电源使能控制

    DCMI 信号与引脚（全部 AF13）：
    ┌──────────┬────────────────────────────┬────────────────────────┐
    │ 信号     │ 引脚                       │ 说明                   │
    ├──────────┼────────────────────────────┼────────────────────────┤
    │ D0~D4    │ PC6 PC7 PC8 PC9 PC11       │ 8 位并行数据           │
    │ D5       │ PD3                        │                        │
    │ D6 D7    │ PB8 PB9                    │                        │
    │ PCLK     │ PA6                        │ 像素时钟（模块自己出） │
    │ HREF     │ PH8                        │ 行有效                 │
    │ VSYNC    │ PB7                        │ 场同步                 │
    │ SCCB SCL │ PB4                        │ 软件模拟               │
    │ SCCB SDA │ PB3                        │ 软件模拟，双向         │
    │ RST      │ PA15                       │ 低电平复位             │
    └──────────┴────────────────────────────┴────────────────────────┘

    ★ 注意 PA8：IO 分配表里 PA8 同时接着 LF0038 红外接收头并有 4.7K 上拉，
      表上明确写着"不建议做普通 IO 使用"。本工程因为模块自带晶振，
      正好完全不需要碰 PA8。

    ★ P6 是"一座两用"：实验一/二的 SSD1306 OLED 用的正是这组脚
      （PB7=CS PB4=RS PH8=WR PB3=RD PA15=RST + 8 根数据线）。
      本工程要用摄像头，就【必须先把 OLED 拔下来】，两者不能同时插。

    ★ 插拔摄像头前先断电。带电插拔 P6 有可能把 DCMI 的输入脚打坏。

----------------------------------------------------------------
 4. 板载 W25Q256 SPI NOR Flash（32MB）—— 不需要接线
----------------------------------------------------------------
    IO 分配表原话："PF6 接 W25Q256 的片选信号，不建议做普通 IO 使用"
    —— 也就是说 PF6~PF9 这四根线在板上已经连到 W25Q256 了，
    本工程直接把它们配成 SPI5 复用/普通输出即可，不用外加任何线。

    SPI5 信号与引脚（SCK/MISO/MOSI 为 AF5，CS 是普通推挽输出+软件 NSS）：
    ┌──────────┬──────┬────────────────────────────────────────────┐
    │ 信号     │ 引脚 │ 说明                                       │
    ├──────────┼──────┼────────────────────────────────────────────┤
    │ CS       │ PF6  │ 普通推挽输出，软件控制；空闲高电平         │
    │ SCK      │ PF7  │ SPI5，AF5；APB2 90MHz / 4 = 22.5MHz        │
    │ MISO     │ PF8  │ SPI5，AF5；开内部上拉避免 CS 无效时悬空    │
    │ MOSI     │ PF9  │ SPI5，AF5                                  │
    └──────────┴──────┴────────────────────────────────────────────┘
    总线参数：8 位、CPOL=0/CPHA=0（模式 0）、MSB 先出、阻塞式收发（未用 DMA）

    ★ PF6~PF9 与 SDRAM / LTDC / DCMI 的引脚【完全不重叠】，
      所以加这一路不影响前三套总线（这是它比"再外挂一个 Flash 模块"省事的地方）。

    ★ 容量 32MB > 16MB，地址是 25 位 → 必须用【4 字节地址模式】：
      上电先发 0xB7 进入 4 字节地址模式，之后用
      0x13(读) / 0x12(页编程) / 0x21(4KB 扇区擦除) / 0xDC(64KB 块擦除) / 0x9F(读 ID)。
      程序上电会读 JEDEC ID 核对（W25Q256 = 0xEF4019）；ID 不符或读不到会
      退化成"仅内存图库"并在屏上提示，此时断电后录入的人脸会丢失。

    ★ 人脸库写在 Flash 的独立数据区：【从 0x01000000（16MiB）起，占 1MiB】。
      刻意避开板上前半部分可能存在的字库等资源，不覆盖已有数据 ——
      这是实验要求里"预留独立的数据区域"的具体落实。

 5. 板载双色 LED 与 4 个按键（都不用接线）
----------------------------------------------------------------
    LED（依据《阿波罗V2 硬件参考手册》LED 原理图）：
        VCC3.3 --[R65 510R]-- DS1(绿) -- PB0
        VCC3.3 --[R62 510R]-- DS0(红) -- PB1
      电流从 VCC 经限流电阻、经 LED 流入 MCU 引脚（MCU 灌电流），
      所以【输出低电平点亮，输出高电平熄灭】。
      本工程的状态对应关系（识别结果）：
          通过  ：绿灯常亮、红灯灭
          不通过：红灯常亮、绿灯灭
          跟随"当前选中的识别方式"的判定；结果界面换方式会立刻跟着变

    按键（全部板载）：
      ┌────────────┬──────┬──────────┬────────────────────────────────────┐
      │ 丝印       │ 引脚 │ 有效电平 │ 本工程作用                         │
      ├────────────┼──────┼──────────┼────────────────────────────────────┤
      │ KEY0 / K0  │ PH3  │ 低       │ 全局：K2 切换模式（录入→识别→统计  │
      │ KEY1 / K1  │ PH2  │ 低       │ →信息→录入）；录入：K0 拍照存一张、│
      │ KEY2 / K2  │ PC13 │ 低       │ K1 删最后一张、UP 选人；识别：K0   │
      │ WK_UP / UP │ PA0  │ 高       │ 拍照识别、K1 切算法、UP 选真值；   │
      │            │      │          │ 统计：K0 标定阈值、K1 清空统计；   │
      │            │      │          │ 信息：K0 清空图库、K1 重建模型     │
      └────────────┴──────┴──────────┴────────────────────────────────────┘
      消抖：10ms 扫一次，连续稳定 20ms 才认，只在按下边沿出一次事件。

 6. ★★ 引脚是怎么推导出来的（这部分是方法）★★
----------------------------------------------------------------
    核心思路：需求 → 外设 → 引脚 → 用《IO 引脚分配表》逐脚排除冲突 → 定表

    第 1 步  把需求翻译成"要几个什么样的外设"
              800x480 彩屏 + 实时预览界面 -> LTDC（硬件扫描的并行 RGB 接口）
              帧缓冲 750KiB              -> 片内 SRAM 只有 256KiB，必须外扩
                                            SDRAM -> 挂在 FMC 上
              摄像头取景拍照             -> DCMI（8 位并行 + PCLK/HREF/VSYNC）
              人脸库断电保存             -> 板载 SPI NOR Flash（SPI5）
              结果指示                   -> 板载 2 个 LED + 4 个按键

    第 2 步  分清"总线类"和"单点类"外设
              【总线类】FMC(39 根) / LTDC(20 根) / DCMI(11 根) / SPI5(4 根)
                 一个信号都少不得，而且板上是硬走线连到器件/座子的，
                 所以【没有选脚的自由】，只能照 IO 分配表抄。
              【单点类】LED / 按键
                 板上也已经定死（PB0 PB1 / PH3 PH2 PC13 PA0），照抄。

    第 3 步  用 IO 分配表逐脚排除冲突（本实验真正难的地方）
              前两个实验（LED_BEEP / TIMER_LAB）敢把 FMC 数据线当普通 IO 用，
              是因为【FMC 没开】，那些脚接到 SDRAM 的 DQ 上，不初始化时是高阻。
              但本实验 FMC 必须开（帧缓冲在人脸库/帧缓冲都在 SDRAM），于是：
                PE7~PE15 / PD14 PD15 / PD0 PD1 / PD8~PD10  -> SDRAM 数据线
                PF0~PF5 / PF12~PF15 / PG0~PG2               -> SDRAM 地址线
                PG4 PG5 / PE0 PE1                           -> Bank 地址 + 字节掩码
                PG8 PG15 / PF11 / PC0 PC2 PC3               -> SDRAM 控制线
              LTDC 吃掉：
                PH9~PH12 / PG6 / PH13~PH15 / PI0~PI2 / PG11 / PI4~PI7
                PG7(CLK) / PF10(DE) / PI9(VSYNC) / PI10(HSYNC)
              DCMI 再吃掉：
                PC6~PC9 / PC11 / PD3 / PB8 PB9 / PA6 / PH8 / PB7
              最后 SPI5 又占掉 PF6~PF9（幸运的是它们不在上面任何一组里）。
              → 结果 PE/PD/PF/PG/PH/PI 几乎被占满，可用脚寥寥无几。

              端口占用统计（LQFP176 引出 PA~PI 共 144 个 IO）：
                实验三 = 84 个；本实验再加 PF6~PF9（SPI5）= 88 个。

    第 4 步  确认每个外设的复用功能编号（AF 写错就是没输出）
              LTDC = AF14    FMC = AF12    DCMI = AF13    SPI5 = AF5
              单总线类（SCCB / LED / 按键 / 背光 / Flash 片选）= 普通 GPIO
              SWD（PA13/PA14）= AF0（复位默认值，不用手动配）

    第 5 步  定表，并把它变成"唯一事实来源"
              全部引脚常量写在 Inc/pinmap.h 里，各 BSP 只 include 它，
              不在别处出现裸引脚号 —— 换板子/换屏只改一个文件。

 8. 常见坑
----------------------------------------------------------------
  1) PB3 / PB4 / PA15 被摄像头占用（它们同时是 JTAG 的 JTDO / NJTRST / JTDI），
     所以调试【只能用 SWD】，不能挂 JTAG。阿波罗板默认就是 SWD，不受影响，
     但如果你的仿真器是 JTAG 模式，请改成 SWD。
  2) P6 是"一座两用"：OLED 和摄像头【互斥】，不要同时插。
     实验一/二的 OLED 用的正是 DCMI 那些脚（PB7/PB4/PH8/PB3/PA15 + 数据线）。
  3) FMC 一开，PE7~PE15 / PD0 PD1 PD8~PD10 / PD14 PD15 / PF 全部（PF6~PF9 除外
     已被 SPI5 用）/ PG0~PG2 PG4 PG5 PG8 PG15 / PC0 PC2 PC3 就是 SDRAM 总线，
     【不能再当普通 IO】。前两个实验借用过的 PE9 / PE10 / PE15 / PD14
     在这里全是 SDRAM 数据线。
  4) PF6 是 W25Q256 的片选：配成普通推挽输出时，先写高电平再切成输出，
     避免上电瞬间把 CS 拉低、误触发 Flash。
  5) W25Q256 必须进【4 字节地址模式】（0xB7），否则读写地址会错位；
     换 W25Q128/W25Q64 时驱动会自动改用 3 字节命令，但 16MB 的芯片
     装不下 0x01000000 起的图库区，会退化成"仅内存图库"。
  6) 摄像头 RGB565 的字节序可能要改（config.h 的 CFG_CAM_BYTE_SWAP）：
     只有"颜色明显不对"才改它；花屏/撕裂不是这个原因（先查 SDRAM 与面板时序）。
  7) SDRAM 是花屏/丢帧的"第一嫌疑人"：FMC 的 39 根脚速度必须开到
     GPIO_SPEED_FREQ_VERY_HIGH，时序按 90MHz 算。上电时程序会自己做
     SDRAM 自检，失败会直接在屏上报出来。
  8) PA8 别碰：它并联着 LF0038 红外接收头（IO 分配表："不建议做普通 IO 使用"）。
     本工程靠"摄像头模块自带晶振"正好避开了这个脚。
  9) PB5 在实验二是 TIM3_CH2（蓝灯），在本工程是【LCD 背光】。
     屏不亮时按这个顺序查：背光/座子 → PB5 电平 → LTDC 时序宏 → SDRAM。

 9. 上电自检与故障排查
----------------------------------------------------------------
  程序上电会依次做这些事，并把结果显示在屏上：
      SDRAM 初始化 + 图案自检（自检区在 0xC1000000，远离所有数据区）
      LCD（LTDC）初始化
      NOR Flash 器件 ID 核对 + 读回上次录入的人脸库（逐条 CRC 校验）
      DCMI 初始化 + OV5640 初始化（SCCB 配寄存器）
      若图库非空，直接重建识别模型；然后进入【录入模式】

  ┌──────────────────────┬──────────────────────────────────────────────┐
  │ 现象                 │ 先查什么（按顺序）                           │
  ├──────────────────────┼──────────────────────────────────────────────┤
  │ 上电没反应、PWR 不亮 │ K1 是否按下 → DC_IN 是否有 6~15V → 保险丝    │
  │ 屏全黑但背光有亮     │ BOOT0/BOOT1 是否为 0 → LTDC 时序宏 → SDRAM 自检│
  │ 屏花/偏移/撕裂       │ 面板时序 HSW/HBP/HFP/VSW/VBP/VFP 与四位极性   │
  │                      │ → SDRAM 速度/时序（多数是 SDRAM 而不是屏）   │
  │ 屏提示 SDRAM 自检失败│ FMC 引脚焊接/虚接、SDRAM 供电、时序按 90MHz  │
  │ 屏提示 Flash 无应答  │ PF6~PF9 是否被其它代码改过；这时图库只在内存 │
  │ 预览花屏或不动       │ USB/排线是否松动 → CFG_CAM_BYTE_SWAP → P6 接触│
  │ 预览偏色             │ CFG_CAM_BYTE_SWAP 改 1 再试                  │
  │ 摄像头初始化失败提示 │ 断电重插 P6（对插方向）→ 按 K1 重新初始化    │
  │ 录入后断电丢失       │ 屏上是否提示"退化为仅内存图库"（Flash 不可用）│
  │ 识别总是"不通过"     │ 阈值是否用验证集标定过（统计界面按 K0）       │
  └──────────────────────┴──────────────────────────────────────────────┘
