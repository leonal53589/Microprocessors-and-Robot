================================================================
 FACE_LAB —— STM32F429 人脸录入与识别（实验四）
================================================================
开发板：正点原子阿波罗 V2 STM32F429（STM32F429IGTx, LQFP176）
配套：  DNF429-EB 嵌入式学习实验箱 + 7 寸 800x480 RGB 屏 + ATK-OV5640 摄像头
存储：  板载 W25Q256 SPI NOR Flash（32MB，SPI5）持久保存人脸库
时钟：  HSE 25MHz -> PLL(25/360/2) -> SYSCLK 180MHz
        HCLK 180MHz / APB1 45MHz / APB2 90MHz
        LTDC 像素时钟 = PLLSAI(240/4)/2 = 30MHz（976x528 ≈ 58.2Hz）
        SDRAM 时钟 = HCLK/2 = 90MHz；SPI5 = APB2/4 = 22.5MHz
调试：  SWD（PA13/PA14），用实验箱自带的 DAP 仿真器

参考：《STM32F429 阿波罗开发指南》第 13/14/25/26/31/39/50 章
      《阿波罗V2 STM32F429开发板IO引脚分配表》（guide 目录）

----------------------------------------------------------------
 一、功能与按键
----------------------------------------------------------------
四种模式（K2 循环切换）：录入 -> 识别 -> 统计 -> 信息 -> 录入

【录入模式】实时预览 + 固定取景框
    UP  选人（1~5 循环）
    K0  拍照并保存一张（每人最多 6 张，要求至少 5 张）
    K1  删掉当前人最后一张（拍糊了重拍用）
    规则：画质不合格（太暗/太亮/未对准）不保存，只在侧栏提示重拍；
          每次按键只存一张；保存后自动重建识别模型

【识别模式】实时预览 + 固定取景框
    UP  切换"真值"：1~5 或 非库内人员（用于统计误拒/误通过）
    K1  切换识别方式（MSE / LBP / COLOR / PCA）
    K0  拍照 -> 用同一张图跑完四种方式 -> 进结果界面
    结果界面：UP 换"以哪个方式为准"（不重拍，直接用已算好的距离重判）
              K1 回预览      K0 回预览并立刻再拍一张

【统计界面】
    UP  切换数据集：验证集（用来标定阈值）/ 最终测试集（只用一次）
    K0  用验证集缓存标定"当前方式"的拒识阈值
    K1  清空当前数据集的统计
    显示：每种方式的 库内次数、正确通过率、误拒率、库外次数、误通过率、模型占用

【信息界面】
    UP  清空验证集缓存      K0 清空整个图库      K1 重建模型
    显示：SDRAM 自检、LCD 初始化、NOR Flash JEDEC ID 与容量、每人已录张数、
          训练样本数、PCA 主成分 k、PCA 训练耗时、各方式模型状态

【双色灯】通过 -> 绿灯 PB0 常亮、红灯 PB1 灭；不通过 -> 红灯常亮、绿灯灭。
          灯跟随"当前选中的方式"的判定；结果界面换方式会立刻跟着变。

 二、三种识别方式（+ 一个对照特征）
----------------------------------------------------------------
统一流程：取景框裁剪 -> 最近邻缩放成 48x48 -> 存 RGB565 + 生成灰度
          所有距离都是"越小越像"，最近邻距离 <= 阈值 才算"通过"（开放集）

1) MSE 模板匹配（algo_mse.c）
     MSE = (1/N) * Σ(q_p - g_p)^2 ，N = 2304
     对亮度、位置偏移最敏感（平方级错位惩罚），但计算量最小（约 7 万次乘加）
     —— 直接复用图库里的灰度图，不额外占内存

2) LBP 分区直方图（algo_hist.c，核心手工特征）
     3x3 邻域 8 位 LBP + 4x4 分区，每区 256 桶，每区归一化到 10000 -> 4096 维
     距离 = 卡方距离 Σ(a-b)^2/(a+b+1) / 10000
     保留空间信息，对光照变化比 MSE 稳

3) 颜色直方图（algo_hist.c，对照特征）
     RGB 各取高 3 位 -> 8x8x8 = 512 桶，整体归一化
     完全没有空间信息：换表情影响小，但背景/衣服颜色一变就跟着变，
     未录入者的误通过率通常明显高于 LBP —— 这正是用来对比"颜色 vs 纹理"的

4) SVD/PCA 特征脸（algo_pca.c）
     均值脸 + 中心化 -> 样本 Gram 矩阵 G = A·A^T（n x n, n<=30）
     Jacobi 旋转求特征值/特征向量（降序），取 k = min(16, n-1) 个有效主成分
     （特征值 <= 1e-6*最大特征值 的成分丢弃，避免除零）
     特征脸 u_j = Σ V[i][j]·a_i 后单位化；投影 = u_j·(x-均值)
     距离 = k 维子空间里的欧氏距离；只对 2304x2304 的小样本等价矩阵做分解，
     绝不直接分解 2304x2304 大矩阵

阈值：都在 Inc/config.h 里（默认只是起点值），必须用【验证样本】标定：
      识别时把真值设好，每次抓拍都会进验证集缓存（最多 12 张），
      然后在统计界面按 K0，程序会在"库内距离"和"库外距离"之间扫一遍，
      取判错次数最少的那个作为阈值，并标记"已标定"。
      最终测试集不入缓存，保证"测试图只用一次、不回头调参"。

 三、存储布局
----------------------------------------------------------------
【NOR Flash（W25Q256，32MB，4 字节地址模式）】
     0x00000000 ~ 0x00FFFFFF   保留（板载字库等资源所在，本工程不碰）
     0x01000000                人脸库区起点（1MiB，见 pinmap.h FACE_FLASH_BASE）
        +0x0000  第 1 个 4KB 扇区：库头（magic/版本/条数/每人张数/CRC32）
        +0x1000 起：每条记录占 2 个扇区（8192B）
     记录格式（小端，显式按字节打包）：
        偏移 0   4B  magic 'FREC'
        偏移 4   1B  版本 | 1B 人员编号 | 1B 该人第几张 | 1B flags
        偏移 8   4B  写入时刻
        偏移 12  4608B  RGB565 人脸图
        偏移 4620 2304B 灰度图
        偏移 6924 4B  前 6924 字节的 CRC32
     写入：擦 2 扇区 -> 分 4 段流式写（不申请大缓冲）-> 回读校验 magic
     读回：逐条校验 magic + CRC32，坏一条只丢一条
     核对器件 ID：0xEF4019(W25Q256/32MB) 0xEF4018(128/16MB) 0xEF4017(64/8MB)
     若 ID 不符或容量 < 17MB -> 自动退化为"仅内存图库"，LCD 明确提示，
     此时断电后需要重新录入（实验要求允许这种降级，但必须在报告里说明）

【SDRAM（32MB，只用前 3MB）】见 pinmap.h
     0xC0000000  LCD 帧缓冲        750KiB
     0xC0100000  摄像头缓冲        150KiB x2（预留 384KiB）
     0xC0160000  人脸图库          30 条 x 6928B = 203KiB（预留 256KiB）
     0xC01A0000  特征区            LBP 240KiB + 颜色 30KiB + 验证缓存 81KiB（预留 512KiB）
     0xC0220000  算法工作区        PCA 模型 229KiB + 训练样本 68KiB（预留 512KiB）
     0xC1000000  SDRAM 自检区      128KiB（远离以上所有分配）
     各区的容量都有编译期断言（face_db.c / face_algo.c 里的 typedef char ..._check），
     一旦哪个数组长大到越界，编译就会直接报错。

 五、编译与下载
----------------------------------------------------------------
【方式1：命令行】在本目录执行 make all，产物在 build\：
      FACE_LAB.elf / .hex / .bin（本工程实测 text ≈ 135KB，片内 RAM bss ≈ 31KB）
      然后双击 flash.bat（自动挑最新的 elf，并先清掉占用 DAP 的 openocd）
      注意：命令行需要 arm-none-eabi-gcc 与 make；本机可以借用 STM32CubeIDE 自带的
      工具链（D:\STM32CubeIDE\STM32CubeIDE\plugins\com.st.stm32cube.ide.mcu.externaltools.*）

【方式2：CubeIDE】
      File -> Import -> General -> Existing Projects into Workspace
      目录选 D:\STM32Projects\FACE_LAB
      调试探头选 OpenOCD + CMSIS-DAP（正点原子 DAP，不是 ST-LINK），
      OpenOCD 脚本用工程里的 openocd_cmsis_dap.cfg

 六、已知事项 / 待上板确认
----------------------------------------------------------------
1. 面板时序与极性（★最重要）
   pinmap.h 的 HSW/HBP/HFP/VSW/VBP/VFP 是按"典型 800x480 + 30MHz"填的，
   bsp_lcd.c 里四位极性也要按实际屏核对。花屏/偏移先查这一组。

2. 摄像头 RGB565 字节序（CFG_CAM_BYTE_SWAP）
   DCMI 8 位模式下先到的是高字节，若预览颜色明显偏色（不是花屏），
   把 config.h 的 CFG_CAM_BYTE_SWAP 改成 1 再试。

3. W25Q256 的参数依赖 APB2 = 90MHz
   SPI5 用 APB2/4 = 22.5MHz；若改了 APB2 分频，SPI 速率会跟着变。
   4 字节地址模式（0xB7）与命令 0x13/0x12/0x21 已在 w25qxx.c 中处理；
   若换成 W25Q128/W25Q64，驱动会自动改用 3 字节命令，但 16MB 芯片
   装不下 0x01000000 起的图库区，会退化为"仅内存图库"。

4. 阈值必须自己标定
   config.h 里的四个阈值只是起点值。请按实验要求：
   先拍 5 人 x 5 张训练图 -> 再拍每人 2 张验证图 + 3 位未录入者各 2 张验证图
   -> 在统计界面按 K0 标定 -> 最后才拍最终测试图（每人 3 张 + 未录入者 3 张）。
   标定结果只在内存里，重新上电回到 config.h 的默认值（没有写进 Flash）。

5. 取景框与拍摄要求
   取景框固定在 QVGA 画面的 (80,30) 起 160x160，裁剪后缩放到 48x48。
   拍摄时人脸要填满取景框、正对镜头、光照均匀；录入与识别必须用同一距离与姿态，
   否则 MSE 这类算法会先被"位置偏差"打败。

6. 本实验不做人脸检测
   用的是"固定取景框 + 人工对准"，符合实验里"人脸检测与识别是不同问题"的定位。

7. 未实现/可扩展
   * 阈值没有掉电保存（可扩展到 Flash 库头的保留字节）
   * 没有用蜂鸣器做提示音（PCF8574 与 PB12 单总线无关，但本工程未启用该芯片）
   * 识别是逐张最近邻，图库 30 张时四种方式合计约十几毫秒（LCD 上会显示实测值）
   * 若要做"连续识别"，可把 DCMI 改成连续模式 + DMA 双缓冲
