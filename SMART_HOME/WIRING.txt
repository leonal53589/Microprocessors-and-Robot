================================================================
 SMART_HOME 接线指南 与 引脚解析
================================================================
板卡：正点原子阿波罗 V2 STM32F429（STM32F429IGTx, LQFP176）
配套：DNF429-EB 嵌入式学习实验箱
外设：7 寸 800x480 RGB 屏 + ATK-OV5640 + DHT11 + 板载 RV1 电压表

本工程和前两个实验（LED_BEEP / TIMER_LAB）最大的区别：
    前两个实验是"挑一个空闲脚，外接 LED / 跳线 / 按键"；
    本实验是 FMC + LTDC + DCMI 【三套总线同时开】，
    PE / PD / PF / PG / PH / PI 几乎被占满，几乎没有"空闲脚"可挑。
    所以本文档的重点不是"怎么接外设"，而是"引脚为什么只能是这些"。

----------------------------------------------------------------
 0. 先看总览：哪些要接线、哪些对插就行
----------------------------------------------------------------
    ┌──────────────┬────────────────────┬──────────────────────┬────────────────────┐
    │ 模块         │ 接到哪里           │ 怎么接               │ 备注               │
    ├──────────────┼────────────────────┼──────────────────────┼────────────────────┤
    │ 7 寸 RGB 屏  │ 板上 RGBLCD 接口   │ 对插（按丝印对齐）   │ 20 根 LTDC + 背光  │
    │ ATK-OV5640   │ 板上 P6（OLED/CAM）│ 对插（2x8 插 2x9）   │ 与 OLED 互斥       │
    │ DHT11        │ 板上单总线座(U10)  │ 对插，或 3 根杜邦线  │ PB12，板上 4.7K    │
    │ 电压表 RV1   │ P10 跳线帽         │ 板上已连，插好跳线帽 │ 不需要外接线       │
    │ 双色 LED     │ 板载 DS0 / DS1     │ 不用接               │ PB0 绿 / PB1 红    │
    │ 4 个按键     │ 板载               │ 不用接               │ K0/K1/K2/UP        │
    │ 仿真器       │ 板上 SWD 座        │ 对插实验箱的 DAP     │ CMSIS-DAP，非 STLK │
    └──────────────┴────────────────────┴──────────────────────┴────────────────────┘

    结论：本工程【一根杜邦线都不需要】就能跑起来
    （前提是屏、摄像头、DHT11 都用板载座子对插；RV1 靠 P10 跳线帽）。
    这是它和前两个实验最大的不同 —— 前两个实验要外接 LED、跳线、按键，
    本工程的外设全是板载件或对插件。

    唯一的例外：如果实验箱上的 7 寸屏不是座子而是用杜邦线引出的版本，
    那就要按丝印把 20 根 LTDC 信号 + 背光逐根接上（见第 1 节）。

----------------------------------------------------------------
 1. 7 寸 800x480 RGB 屏 —— 接板上 RGBLCD 接口
----------------------------------------------------------------
    接口：板上丝印 RGBLCD 的座子（与 TFTLCD 共用一组 LTDC 信号线）
    接法：按板上丝印对齐插入，注意座子的缺口方向，插反了会没显示
    信号：20 根 LTDC 信号（数据 16 根 + CLK/DE/VSYNC/HSYNC 4 根）
          + 1 根背光控制 PB5
    极性：行/场同步低有效、DE 高有效、像素时钟上升沿采样
          （这四位写在 bsp_lcd.c 的 LTDC_Init 里，换屏第一件事就是核对这里）

    LTDC 信号与引脚（全部 AF14）：
    ┌──────────┬────────────────────┬──────────────────────────────┐
    │ 信号     │ 引脚               │ 说明                         │
    ├──────────┼────────────────────┼──────────────────────────────┤
    │ R3~R6    │ PH9 PH10 PH11 PH12 │ 红色高 4 位                  │
    │ R7       │ PG6                │ 红色最高位                   │
    │ G2~G4    │ PH13 PH14 PH15     │ 绿色低 3 位                  │
    │ G5~G7    │ PI0 PI1 PI2        │ 绿色高 3 位                  │
    │ B3       │ PG11               │ 蓝色低 3 位的最高一位        │
    │ B4~B7    │ PI4 PI5 PI6 PI7    │ 蓝色高 4 位                  │
    │ CLK      │ PG7                │ 像素时钟（PLLSAI 出 30MHz）  │
    │ DE       │ PF10               │ 数据使能                     │
    │ VSYNC    │ PI9                │ 场同步                       │
    │ HSYNC    │ PI10               │ 行同步                       │
    │ 背光 BL  │ PB5                │ 普通 GPIO，高电平点亮(待实测) │
    └──────────┴────────────────────┴──────────────────────────────┘

    ★ 为什么只有 R3~R7 / G2~G7 / B3~B7，没有 R0~R2 / G0~G1 / B0~B2？
      板上的 RGBLCD 接口只引出了高 5/6/5 位，低 3 位没接。这正好就是
      LTDC 的 RGB565 像素格式（R[7:3] G[7:2] B[7:3]），所以本工程用
      RGB565 最自然，也比 RGB888 省一半 SDRAM 带宽（750KiB/帧 而非 1.5MiB）。

    ★ 与 OLED 实验的互斥关系
      实验一/二把 SSD1306 OLED 插在 P6（8080 并口），用的是
      PB7=CS、PB4=RS、PH8=WR、PB3=RD、PA15=RST 和 8 根数据线。
      本实验改用 7 寸 RGB 屏之后，P6 就空出来专门给摄像头了 ——
      也就是说【OLED 和摄像头不能同时插】，它们是同一个座子。

----------------------------------------------------------------
 2. ATK-OV5640 —— 插板上 P6（丝印 OLED/CAMERA）
----------------------------------------------------------------
    接法：直接插 2x9 的 P6 排针，靠 3V3/GND 那一端开始插，
          2x8 的模块插 2x9 的排针，另一端空 2 个孔是正常的
    SCCB：SCL = PB4，SDA = PB3，【软件模拟】（板上已有 4.7K 外部上拉）
          阿波罗板没有给摄像头留硬件 IIC，只能软件模拟，约 200kHz
          （SCL 边沿间延时 2us；SCCB 上限 400kHz）
    复位：RST = PA15，低电平有效；板上该脚有 10K 上拉
    时钟：模块【自带 24MHz 有源晶振】→ 所以主控【不驱动 PA8(DCMI_XCLK)】，
          本驱动完全不配置任何时钟输出
    数据：DCMI 8 位并行 + PCLK/HREF/VSYNC，全部 AF13
    PWDN：P6 座子上根本没有引 PWDN 脚，所以不需要电源使能控制

    DCMI 信号与引脚（全部 AF13）：
    ┌──────────┬────────────────────────────┬────────────────────────┐
    │ 信号     │ 引脚                       │ 说明                   │
    ├──────────┼────────────────────────────┼────────────────────────┤
    │ D0~D4    │ PC6 PC7 PC8 PC9 PC11       │ 8 位并行数据           │
    │ D5       │ PD3                        │                        │
    │ D6 D7    │ PB8 PB9                    │                        │
    │ PCLK     │ PA6                        │ 像素时钟（模块自己出） │
    │ HREF     │ PH8                        │ 行有效                 │
    │ VSYNC    │ PB7                        │ 场同步                 │
    │ SCCB SCL │ PB4                        │ 软件模拟               │
    │ SCCB SDA │ PB3                        │ 软件模拟，双向         │
    │ RST      │ PA15                       │ 低电平复位             │
    └──────────┴────────────────────────────┴────────────────────────┘

    ★ 注意 PA8：IO 分配表里 PA8 同时接着 LF0038 红外接收头并有 4.7K 上拉，
      表上明确写着"不建议做普通 IO 使用"。本工程因为模块自带晶振，
      正好完全不需要碰 PA8 —— 这也是选"自带晶振的模块"的一个好处。

    ★ 插拔摄像头前先断电。带电插拔 P6 有可能把 DCMI 的输入脚打坏。

----------------------------------------------------------------
 3. DHT11 温湿度 —— PB12 单总线
----------------------------------------------------------------
    接法：板上单总线座（IO 分配表写作 U10 / 1WIRE_DQ），模块对插即可；
          如果用的是 3 根杜邦线引出的模块，就按下面接：
              VCC -> 3.3V（不要接 5V）
              DQ  -> PB12
              GND -> GND
    上拉：板上 PB12 已经有 4.7K 上拉，不需要再加
    方向：本工程把 PB12 配成【开漏输出(OD) + 上拉】拉低，
          读的时候切成【输入 + 上拉】，全程不和从机对拉
    时序：主机拉低 20ms（>=18ms）起始 -> 从机 80us 应答 ->
          40 位数据（每位 = 50us 低 + 26~28us 判 0 / 70us 判 1）
    采样：CFG_DHT_PERIOD_MS = 2000ms，另外按 K2 可以随时手动测一次

    ★ PB12 是"一座两用"的脚（见第 8 节第 4 条）：
      它同时接 PCF8574 的 INT 和单总线座子的 DQ。
      本工程不用 PCF8574，它的 INT 是开漏输出、靠上拉保持高电平，
      不会干扰 DHT11。但两个功能不能同时用。

----------------------------------------------------------------
 4. 电子电压表 —— RV1 -> P10 跳线 -> PA5
----------------------------------------------------------------
    通路上是【板上既定的】：板载电位器 RV1 的分压点经 P10 跳线帽送到 PA5，
    PA5 = ADC1_IN5。所以本工程不需要外接线，但必须：
        1) 把 P10 的跳线帽插好（拔掉的话 PA5 就"完全独立"，测不到 RV1）
        2) 量程只有 0~3.3V，【绝对不能接 5V 或未知电压】
        3) PA5 配成【模拟输入】，不能开上下拉（会改变 RV1 的分压比）

    换算：V(mV) = raw x 3300 / 4095，屏幕上同时显示原始 ADC 值 -> 换算电压
    采样：480 个 ADC 周期（最长档，给高源阻抗留建立时间）+ 16 次平均
    注意：IO 分配表提到 PA5 同时是 TPAD 检测脚 —— 本工程不用 TPAD，
          拔了 P10 跳线帽它才"完全独立"。

----------------------------------------------------------------
 5. 板载双色 LED 与 4 个按键（都不用接线）
----------------------------------------------------------------
    LED（依据《阿波罗V2 硬件参考手册》LED 原理图）：
        VCC3.3 --[R65 510R]-- DS1(绿) -- PB0
        VCC3.3 --[R62 510R]-- DS0(红) -- PB1
      电流从 VCC 经限流电阻、经 LED 流入 MCU 引脚（MCU 灌电流），
      所以【输出低电平点亮，输出高电平熄灭】。
      本工程的状态对应关系（代码里的 ALARM_* 三态）：
          正常：绿灯常亮、红灯灭
          越限：绿灯灭、红灯 2Hz 闪烁（250ms 翻转一次）
          故障：绿灯灭、红灯常亮
      上电默认两个灯都灭（红灯是"故障/报警"色，不能默认亮）。

    按键（全部板载，与实验二一致，方便沿用按键习惯）：
      ┌────────────┬──────┬──────────┬────────────────────────────────┐
      │ 丝印       │ 引脚 │ 有效电平 │ 本工程作用                     │
      ├────────────┼──────┼──────────┼────────────────────────────────┤
      │ KEY0 / K0  │ PH3  │ 低       │ 切换页面（首页 <-> 摄像头页）  │
      │ KEY1 / K1  │ PH2  │ 低       │ 摄像头页：重新初始化 OV5640    │
      │ KEY2 / K2  │ PC13 │ 低       │ 立即测温湿度一次               │
      │ WK_UP / UP │ PA0  │ 高       │ 同 K0（切换页面）              │
      └────────────┴──────┴──────────┴────────────────────────────────┘
      消抖：10ms 扫一次，连续稳定 20ms 才认，只在按下边沿出一次事件。

 6. ★★ 引脚是怎么推导出来的（这部分是方法，学会了自己就能排）★★
----------------------------------------------------------------
    核心思路：需求 → 外设 → 引脚 → 用《IO 引脚分配表》逐脚排除冲突 → 最终定表

    第 1 步  把需求翻译成"要几个什么样的外设"
              显示 800x480 彩屏   -> LTDC（硬件扫描的并行 RGB 接口）
              帧缓冲 750KiB       -> 片内 SRAM 只有 256KiB，放不下 -> 必须外扩 SDRAM
                                     -> SDRAM 要挂在 FMC 上
              摄像头实时预览      -> DCMI（8 位并行 + PCLK + HREF + VSYNC）
              温湿度              -> 单总线（1 根双向线）
              电压                -> ADC 单通道（1 根模拟输入）
              人机界面            -> 2 个 LED + 4 个按键（板载，不占外接资源）

    第 2 步  分清"总线类"和"单点类"外设 —— 这决定了有没有选脚的自由
              【总线类】FMC(39 根) / LTDC(20 根) / DCMI(11 根)
                 一个信号都少不得，而且板上是硬走线连到座子的，
                 所以【没有选脚的自由】，只能照 IO 分配表抄。
              【单点类】DHT11 / ADC / LED / 按键
                 板上也已经定死了（PB12 / PA5 / PB0 PB1 / PH3 PH2 PC13 PA0），
                 同样照抄。
              → 所以本实验的"引脚推导"重点不是"挑一个空闲脚"，
                而是【把板上既定走线核对清楚】，并且保证
                "同一个脚的 MODER/AFR 只有一条代码路径去改它"
                （本工程的做法：每个外设的 GPIO 初始化都写在自己的 BSP 文件里，
                  gpio.c 只管 4 个按键，hal_msp.c 只留最基础的 HAL_MspInit）。

    第 3 步  用 IO 分配表逐脚排除冲突（本实验真正难的地方）
              前两个实验敢把 FMC 数据线当普通 IO 用，是因为【FMC 没开】，
              那些脚接到 SDRAM 的 DQ 上，不初始化时是高阻，安全。
              但本实验 FMC 必须开起来（帧缓冲在 SDRAM 里），于是：
                PE7~PE15 / PD14 PD15 / PD0 PD1 / PD8~PD10  -> SDRAM 数据线
                PF0~PF5 / PF12~PF15 / PG0~PG2               -> SDRAM 地址线
                PG4 PG5 / PE0 PE1                           -> Bank 地址线 + 字节掩码
                PG8 PG15 / PF11 / PC0 PC2 PC3               -> SDRAM 控制线
              紧接着 LTDC 又吃掉：
                PH9~PH12 / PG6 / PH13~PH15 / PI0~PI2 / PG11 / PI4~PI7
                PG7(CLK) / PF10(DE) / PI9(VSYNC) / PI10(HSYNC)
              然后 DCMI 再吃掉：
                PC6~PC9 / PC11 / PD3 / PB8 PB9 / PA6 / PH8 / PB7
              → 结果就是 PE/PD/PF/PG/PH/PI 几乎被占满。

              端口占用统计（LQFP176 引出 PA~PI 共 144 个 IO）：
              ┌──────┬────────┬──────────────────────────────────────────────┐
              │ 端口 │ 已用   │ 本工程用掉的脚                               │
              ├──────┼────────┼──────────────────────────────────────────────┤
              │ PA   │  6/16  │ PA0 按键 / PA5 ADC / PA6 DCMI_PCLK           │
              │      │        │ PA13 PA14 SWD / PA15 摄像头复位              │
              │ PB   │  9/16  │ PB0 PB1 LED / PB3 PB4 SCCB / PB5 背光        │
              │      │        │ PB7 PB8 PB9 DCMI / PB12 DHT11                │
              │ PC   │  9/16  │ PC0 PC2 PC3 FMC 控制 / PC6~PC9 PC11 DCMI     │
              │      │        │ PC13 按键                                    │
              │ PD   │  8/16  │ PD0 PD1 PD8 PD9 PD10 PD14 PD15 FMC 数据      │
              │      │        │ PD3 DCMI_D5                                  │
              │ PE   │ 11/16  │ PE0 PE1 字节掩码 / PE7~PE15 SDRAM 数据 D4~D12│
              │ PF   │ 12/16  │ PF0~PF5 PF12~PF15 地址 / PF10 LTDC_DE        │
              │      │        │ PF11 SDRAM_RAS                               │
              │ PG   │ 10/16  │ PG0~PG2 地址 / PG4 PG5 Bank / PG6 LTDC_R7    │
              │      │        │ PG7 LTDC_CLK / PG8 SDCLK / PG11 LTDC_B3      │
              │      │        │ PG15 SDNCAS                                  │
              │ PH   │ 10/16  │ PH2 PH3 按键 / PH8 DCMI_HREF / PH9~PH15 LTDC │
              │ PI   │  9/16  │ PI0~PI2 PI4~PI7 LTDC / PI9 PI10 同步信号     │
              └──────┴────────┴──────────────────────────────────────────────┘
              合计 84 个 IO —— 一个 144 脚的片子用掉 84 个脚，
              而剩下的"干净可用"的脚寥寥无几（这也就是本实验"资源核对"
              这个知识点真正的难度所在）。

    第 4 步  确认每个外设的复用功能编号（AF 必须和手册一致，写错就是没输出）
              LTDC  = AF14
              FMC   = AF12
              DCMI  = AF13
              单总线 / SCCB / LED / 按键 / 背光 / ADC = 普通 GPIO 或模拟输入
              SWD（PA13/PA14）= AF0（复位默认值，不用手动配）

    第 5 步  定表，并把它变成"唯一事实来源"
              全部引脚常量写在 Inc/pinmap.h 里，各 BSP 只 include 它，
              不在别处出现裸引脚号 —— 这样换板子/换屏只改一个文件。
              （前两个实验的 pinmap.h 也是这个套路，本工程沿用。）

    ★ 判断"某个 IO 能不能借用"的三条经验（本实验基本用不上，
      因为外设把脚占满了，但方法要记住）：
      1) 接【输入型】外设的脚（如 LCD_BL、未初始化的 SDRAM DQ）—— 通常高阻，可借用
      2) 接【输出型】外设的脚（如以太网 PHY 的 CRS_DV）—— 不能当推挽输出，会对拉
      3) 时序敏感的脚（SDRAM 数据/地址线）—— 一旦 FMC 开起来就绝对不能动

  未使用、且【建议不要占用】：PA8（DCMI_XCLK / LF0038 红外接收头，有 4.7K 上拉）

----------------------------------------------------------------
 8. 常见坑
----------------------------------------------------------------
  1) PB3 / PB4 / PA15 被摄像头占用（它们同时是 JTAG 的 JTDO / NJTRST / JTDI），
     所以调试【只能用 SWD】，不能挂 JTAG。阿波罗板默认就是 SWD，不受影响，
     但如果你的仿真器是 JTAG 模式，请改成 SWD。
  2) P6 是"一座两用"：OLED 和摄像头【互斥】，不要同时插。
     实验一/二的 OLED 用的正是 DCMI 的那些脚（PB7/PB4/PH8/PB3/PA15 + 数据线）。
  3) FMC 一开，PE7~PE15 / PD0 PD1 PD8~PD10 / PD14 PD15 / PF 全部 / PG0~PG2 PG4 PG5
     PG8 PG15 / PC0 PC2 PC3 就是 SDRAM 总线了，【不能再当普通 IO】。
     前两个实验借用过的 PE9 / PE10 / PE15 / PD14 在这里全是 SDRAM 数据线。
  4) PB12 与 PCF8574 的 INT 共用。本工程不用 PCF8574（它的 INT 开漏 + 上拉保持高电平，
     不干扰 DHT11）；但若要用 PCF8574 中断，必须先保证它不会在 DHT11 通信期间拉低总线。
  5) PB5 在本工程是【LCD 背光】，不再是实验二的 TIM3_CH2 蓝灯。
     屏不亮时按这个顺序查：P10/背光跳线 -> PB5 电平 -> LTDC 时序宏 -> SDRAM。
  6) DHT11 必须用【开漏 + 上拉】，不能用推挽输出（会和从机对拉）；
     另外读取期间要关中断，所以别的中断服务函数不要写得太长
     （本工程的中断只有 SysTick / DCMI / DMA，回调里只置标志）。
  7) 电压表只能测 0~3.3V，【绝不接 5V】；PA5 配成模拟输入后不能开上下拉，
     P10 跳线帽不插的话读数就是悬空的。
  8) SDRAM 是花屏/丢帧的"第一嫌疑人"：FMC 的 39 根脚速度必须开到
     GPIO_SPEED_FREQ_VERY_HIGH，时序按 90MHz 算。屏幕花而不黑时，先怀疑它，
     再怀疑面板时序宏。上电时程序会自己做 SDRAM 自检，失败会直接在屏上报出来。
